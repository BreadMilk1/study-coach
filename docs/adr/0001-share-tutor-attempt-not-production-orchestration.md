# Share a Tutor Attempt, Not Production Orchestration

Study Coach 的 Production Graph 与 Learning Run Harness 共享一个 graph-free `TutorAttemptEngine`，负责单次 retrieval、版本化 Prompt 构造、token/trace event 和 Candidate 输出；Judge retry、MemoryWriter、Chat persistence 与 Router 仍由 Production Graph 拥有。Evaluation Runner 直接调用一次 TutorAttempt，并使用隔离 corpus 与 `runtime_judge=off`，因为复用完整 Graph 会让 Judge 改写被测答案并引入业务副作用，而复制一套 Eval Tutor 又会造成生产与评测逻辑漂移。

## Consequences

- Production Graph 必须通过 adapter 保持现有 token、citation、`last_context` 和 retry 行为。
- Production Graph 的 Judge 由内部构建参数 `judge_policy` 分为两条路径：默认 `legacy` 逐字节保留历史行为（解析失败的 neutral 0.6、确定性 GRADE/CHECK-IN 的 1.0），仅生产 API `get_graph` 显式选择 `production_v1`——严格 rubric 校验（完整 JSON object 或整体单 fence、全部维度真实有限数值 1–5、重复键/截断/散文拒绝）、无 neutral fallback、负面完成信号阻断。生产 Judge 故障（无效输出、请求失败、受控 `factory_error`）一律 unavailable：保留已输出正文并按最新候选原 message id 追加一次固定 Self-check incomplete 后缀，`judge_score=None`、不伪造 pass/weak、不自动重试或重生成、跳过 MemoryWriter 并清空 pending，已提交 Goal/Plan/Question 不回滚；确定性 GRADE/CHECK-IN 为 skipped（score=None、无 Judge 调用）且其确定性副作用照常。每个生产新 turn 在 router 入口重置 Judge 派生状态与 retry 预算，生产 retry hint 只含已验证 score 与固定维度名，不含 Judge 自由 reasoning。生产 judge 节点只在局部读取 `reasoning` 用于校验，从不写入 `state.judge_reasoning`、trace、`messages` 或任何 `InMemorySaver` checkpoint——保留 router 的清空结果，使 Judge 自由 reasoning 既不跨 turn 也不跨历史 checkpoint 泄漏。`reasoning` 键缺失按合同默认为 `""`（合法 valid），`reasoning: null` 或非 str 类型视为不可用 payload（不可评分、不造分数），窄边界。`json.loads` 在递归过深时抛出的 `RecursionError` 只在 `_parse_strict_object` 的单个 `json.loads` 调用紧邻处被映射到内部 invalid 标记，不得扩大到 prompt / formatter / state / writer 的 `RecursionError` 或一般 `RuntimeError`，也不降低 `sys.setrecursionlimit` 或加任意 retry/救活。锁定 langchain-google-genai 4.2.0 把 `google.genai.errors.ClientError` 通过 `_handle_client_error` 包装为 `ChatGoogleGenerativeAIError`，生产 judge 的 `is_model_service_error` 必须按名字/MRO 识别此 wrapper class；不捕整个 `GoogleGenerativeAIError` 基类、不全函数 `except Exception`、不读取或持久化原始异常 `str`/`repr`/`args`/`request`/`response`；原 `normalize_llm_error` 仍是唯一异常投影。`valid` 分数只表示评分 payload 合法，不是 provider 完成证据；缺失/未指定的完成元数据不会被补写为完成，完整跨 provider 完成证据、hash 与版本化评分审计留 D5。
- 共享 Attempt 的文本合同由 production 与 evaluation 共同继承，不能按各自方便分叉：内容的正文提取、跳过清单与固定拒绝语义在 `app.llm.content` 单点定义，两侧对非法或结构变化的内容都没有回退答案。差别只在谁来消费异常——Production Graph 让该次调用失败并截断 SSE，Evaluation Runner 用既有 `generation` / `model_unavailable` → `system_failed` 终止 Run，不冻结 CandidateArtifact/hash、不进入 scorer。任一侧都不因此放宽边界，也不新增 Judge verdict、错误码或 retry。文本边界只覆盖 LangChain message content；原始 Responses API / Google payload、provider factory、`bind_tools` 与 message history 不在其中，工具循环仍持有完整 AIMessage 与 tool_calls。
- Evaluation profile 评估的是一次基础 TutorAttempt，不等同完整生产路径。
- 未来若增加 `production-fidelity` profile，必须分别保留 first attempt 与 Judge 修正后的 final answer。
- Evaluation 使用三张 append-only 表（`eval_runs` / `eval_score_sets` / `eval_scorer_executions`）和 process-local single-worker lease；Factory reset 必须先删 executions，再删 ScoreSets，再删 Runs。
- Fresh clone 的演示种子是 committed curated fixture，不是本机 ignored raw output。
